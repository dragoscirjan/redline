# Specify

## Workflow

Read the requirements and available code and tests before writing. Declare `requires: ["grilling"]` and use the interview only for unresolved specification choices. The requirement resolves to the catalogued upstream skill; if it is not installed, stop for approved setup rather than downloading implicitly. Reuse confirmed initiative decisions and look up facts instead of asking the user to do so. Clarify unresolved choices before drafting. Once choices are settled, record them without inventing new ones.

Preserve agreed values and interface decisions. Describe observable behavior, failures, and boundaries, then check whether a fresh reader would need to guess requirements. Resolve destination and format after clarification, save the specification, verify its content, and report its path or URL. Reuse an existing issue, document, or section when chosen. Report blocked or unverified saves honestly.

Keep the output small. Do not require long user-story lists, one universal test interface, tracker labels, fixed design paths, or an implementation handoff. Save only at an agreed, authorized destination. Reusing initiative's delivery pattern does not make initiative a skill dependency.
